# CodexPC

**Локальный MCP-шлюз, который позволяет ChatGPT безопасно работать с вашим Windows‑ПК: читать и изменять проекты, выполнять команды, управлять рабочим столом и подключать другие MCP‑серверы.**

CodexPC — локальная надстройка над оригинальным Codex app-server. Она предоставляет ChatGPT набор специализированных инструментов для работы с файлами, терминалом, рабочим столом Windows, долгоживущими процессами и другими MCP‑серверами.

Вместо одного неограниченного терминального интерфейса модель получает отдельные инструменты с понятными границами доступа, проверкой путей, журналированием и подтверждением чувствительных действий.

## Зачем нужен CodexPC

| | |
| --- | --- |
| **Одна установка** | `install.cmd` подготавливает нужную версию Go, Python для локального интерфейса, Codex CLI, официальный `tunnel-client`, зависимости, сборку и проверку запуска. |
| **Оригинальный Codex внутри** | Операции с файлами, правилами проекта и подключёнными MCP‑серверами используют Codex app-server, а не отдельную несовместимую реализацию. |
| **Поддержка долгих процессов** | Команды Windows могут продолжать работу после завершения одного MCP‑запроса. Их можно опрашивать, передавать данные через стандартный ввод или останавливать позже. |
| **Защищённая работа с секретами** | Учётные данные хранятся локально. Чувствительные операции и просмотр сохранённых значений могут требовать явного подтверждения пользователя. |
| **Локальный интерфейс управления** | Сессии, история вызовов инструментов, фоновые процессы, подтверждения, ошибки, секреты и настройки собраны в одном интерфейсе. |
| **Управление Windows без обходных решений** | Скриншоты, мышь, клавиатура и прокрутка доступны как отдельные инструменты. |

## Быстрый старт

### 1. Скачайте CodexPC

Клонируйте репозиторий или скачайте его как ZIP‑архив:

```powershell
git clone https://github.com/niktoimiyazap/codex-pc.git
cd codex-pc
```

### 2. Запустите установку

Откройте `install.cmd` двойным щелчком или выполните:

```bat
install.cmd
```

Установщик можно запускать повторно. Уже установленные совместимые компоненты будут использованы повторно, а отсутствующие или устаревшие — установлены или обновлены.

CodexPC подготавливает:

- версию Go, указанную в `go.mod`;
- Python для локального интерфейса;
- Codex CLI и его авторизацию;
- официальный OpenAI `tunnel-client`;
- Go‑модули, тесты, рабочую сборку и проверку запуска.

### 3. Создайте защищённый MCP‑туннель OpenAI

Откройте [OpenAI Platform → Organization → Tunnels](https://platform.openai.com/settings/organization/tunnels) и создайте туннель для CodexPC.

Для создания и использования туннеля нужны следующие разрешения:

- **Tunnels: Read + Manage** — для создания и изменения туннеля;
- **Tunnels: Read + Use** — для учётной записи или сервиса, который будет запускать туннель и подключать его к ChatGPT.

При создании привяжите туннель к **тому рабочему пространству ChatGPT, в котором будет использоваться CodexPC**.

После создания скопируйте идентификатор туннеля. Он имеет вид:

```text
tunnel_0123456789abcdef0123456789abcdef
```

Затем откройте [OpenAI Platform → Organization → API keys](https://platform.openai.com/settings/organization/api-keys) и создайте ограниченный ключ API (**Restricted API key**) с разрешением **Tunnels: Read + Use**.

Этот ключ используется только локальным `tunnel-client` для запуска соединения. **В интерфейс ChatGPT его вводить не нужно.**

Подробное описание разрешений, ключей и диагностики подключения находится в разделе [«Первичная настройка и туннель»](docs/TUNNEL_SETUP.md).

### 4. Завершите первоначальную настройку CodexPC

После установки откроется локальная страница настройки. Укажите:

- рабочую папку по умолчанию;
- профиль инструментов `core` или `full`;
- Tunnel ID, полученный на предыдущем шаге;
- ограниченный ключ API для запуска туннеля;
- при необходимости — имя профиля туннеля и метку организации.

Обычные параметры сохраняются в конфигурации CodexPC. Ключ API шифруется средствами **Windows DPAPI** для текущей учётной записи Windows и не сохраняется в TOML‑файлах или локальном хранилище браузера.

Перед применением новых данных CodexPC проверяет их во временном изолированном профиле с помощью `tunnel-client doctor`. Ошибка в Tunnel ID или ключе не перезапишет уже рабочую конфигурацию.

### 5. Подключите CodexPC в ChatGPT

Оставьте CodexPC запущенным и откройте веб‑версию ChatGPT.

Если для вашего тарифа или рабочего пространства требуется режим разработчика, включите **Developer mode**.

Затем создайте пользовательское приложение в ChatGPT:

1. откройте **Settings → Apps → Create**; для администраторов рабочего пространства этот пункт также может находиться в **Workspace settings → Apps → Create**;
2. в поле **Connection** выберите **Tunnel**;
3. выберите туннель CodexPC из списка или вставьте его `tunnel_...` ID;
4. нажмите **Scan Tools** и дождитесь, пока ChatGPT обнаружит инструменты CodexPC;
5. нажмите **Create**;
6. при отправке сообщения выберите созданное приложение CodexPC.

Ключ API для запуска туннеля всё это время остаётся только на вашем компьютере. ChatGPT получает доступ к объекту туннеля, а не к самому ключу.

Поддержка пользовательских MCP‑приложений зависит от тарифа и типа рабочего пространства. На момент написания документации полный набор действий чтения и изменения доступен в Business и Enterprise/Edu; в Pro пользовательские MCP‑приложения доступны через режим разработчика с ограничениями на набор действий. Интерфейс функции пока развивается, поэтому названия пунктов могут немного меняться.

### 6. Обычный запуск

После первоначальной настройки используйте:

```bat
start.cmd
```

Скрипт запускает локальный интерфейс, загружает сохранённую конфигурацию и поддерживает соединение с OpenAI Tunnel в рабочем состоянии.

## Какие инструменты получает ChatGPT

CodexPC разделяет действия на специализированные инструменты вместо одного универсального терминального вызова.

| Область | Примеры |
| --- | --- |
| **Сессии и правила проекта** | `session_create`, `session_list`, `read_rules` |
| **Файловая система** | `fs_read_file`, `fs_edit_file`, `fs_write_file`, `fs_search`, `fs_copy`, `fs_remove` |
| **Терминал** | `command_inspect`, `command_exec`, `shell_exec`, `command_poll`, `command_write`, `command_terminate` |
| **Рабочий стол** | `computer` — снимки экрана, мышь, клавиатура и прокрутка |
| **Другие MCP‑серверы** | `mcp_discover`, `mcp_call`, `mcp_resource_read`, `mcp_reload`, `mcp_oauth_login` |
| **Секреты** | `secret_vault`, защищённый подтверждением `credential_value`, ссылки на сохранённые учётные данные для команд |
| **Управление CodexPC** | `connector_status`, аварийное управление процессами, групповые вызовы через `multi_tool` |

Профиль `core` по умолчанию оставляет только основной набор инструментов. Профиль `full` дополнительно включает инструменты совместимости и диагностики.

## Как это работает

```text
start.cmd
   │
   └─ scripts/start-codexpc.ps1
          ├─ frontend/server.pyw ───────► http://127.0.0.1:8765
          └─ tunnel-client
                 │ MCP через stdio
                 ▼
           dist/codexpc-go.exe
                 │
                 ├─ Codex app-server ───► файлы / правила / MCP-серверы
                 ├─ диспетчер команд Windows
                 ├─ управление рабочим столом
                 └─ локальное состояние и журналы
```

CodexPC поддерживает одно долгоживущее соединение с Codex app-server и добавляет поверх него управление сессиями, политику разрешённых путей, кэш списка MCP‑инструментов, нормализацию ответов, управление процессами, подтверждения чувствительных действий и локальный интерфейс.

Подробная схема компонентов и прохождения запросов приведена в [документе об архитектуре](docs/ARCHITECTURE.md).

## Модель безопасности

CodexPC — привилегированное локальное программное обеспечение. Модель доверия рассчитана на **одного доверенного пользователя Windows**, а локальный интерфейс не предназначен для публикации в интернет.

- Интерфейс слушает только `127.0.0.1` и использует локальный механизм авторизации.
- Пути к файлам проверяются по списку `allowed_roots` до выполнения привилегированных операций.
- Ключ API для запуска туннеля защищён Windows DPAPI.
- Секретные значения по возможности передаются через непрозрачные ссылки на учётные данные, а не открытым текстом.
- Чувствительные операции могут требовать подтверждения в локальном интерфейсе.
- Логи и возвращаемые данные ограничиваются по объёму и проходят очистку от секретов.
- Новая конфигурация туннеля проверяется до замены уже работающей.

Не публикуйте локальный интерфейс CodexPC и сам коннектор напрямую в интернет. Перед изменением границ доступа прочитайте [SECURITY.md](SECURITY.md).

## Конфигурация

Рекомендуемый способ настройки — локальный интерфейс CodexPC.

По умолчанию пользовательские данные хранятся здесь:

```text
%LOCALAPPDATA%\CodexPCConnector
```

Несекретные параметры находятся в `config.toml`. Минимальный пример ручной настройки приведён в [`config.example.toml`](config.example.toml):

```toml
workspace = "C:/Users/you/projects"
allowed_roots = ["C:/Users/you/projects"]
tool_profile = "core"
```

Переменная окружения `CODEXPC_STATE_DIR` позволяет перенести весь каталог состояния. Полный список параметров и переменных запуска приведён в [документе о конфигурации](docs/CONFIGURATION.md).

## Структура репозитория

```text
codex-pc/
├─ cmd/codexpc/        точка входа приложения на Go
├─ internal/           ядро, клиент app-server, MCP, безопасность, управление Windows
├─ frontend/           локальный интерфейс настройки и мониторинга
├─ scripts/            установка, запуск, сборка и управление процессами
├─ docs/               архитектура, конфигурация и инструкции по настройке
├─ install.cmd         установка и восстановление окружения
├─ start.cmd           обычный запуск CodexPC
├─ config.example.toml пример ручной конфигурации
└─ go.mod
```

Каталоги `dist/` и `.local/` создаются локально во время работы и сборки и не включаются в Git.

## Сборка из исходников

Для разработки на Windows:

```bat
scripts\build.cmd -NoDesktopCopy
```

Сценарий сборки выполняет форматирование, `go test ./...`, рабочую сборку, проверку взаимодействия с Codex app-server и размещает готовый исполняемый файл в `dist/`.

Те же основные шаги можно выполнить вручную:

```powershell
go fmt ./cmd/... ./internal/...
go test ./...
go build -trimpath -o dist/codexpc-go.exe ./cmd/codexpc
```
